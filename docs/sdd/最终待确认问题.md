## 已收敛的主要结论

- 创建输入改为业务 JSON 加直接上传的 PDF，不再下载 fileUrl/replyImageUrl；文本、扫描 PDF 均支持。
- 创建成功立即响应，后台处理并本地持久化，上游主动轮询；任务状态为 PENDING、PROCESSING、DONE、FAILED、TERMINATED。
- 同业务新任务终止全部未完成旧任务，自己重新排到全局队尾；不打断其他业务执行。已结束的历史记录不随新任务改变，但相同任务键重建的覆盖行为见 T03。
- 一个本地工作任务串行处理；替换执行中任务时关闭本地请求、丢弃旧输出，允许模型服务端旧推理尚未结束；随后按队列顺序执行下一任务。本期无人工终止接口。
- 按批复的可售产品严格匹配。同一产品多条授信记录只查一次、汇总条件；全部产品均处理，有缺失或处理不完整则整次失败。
- 只输出材料。确认不适用的排除；其余包括待确认项按适用输出。不同担保人等对象分别展开，具体要求写入材料名称。
- DONE 以第二轮 R09 新示例为基础：根节点有身份标识、status、message、data；条目保留该示例的编号、类型、五个展示字段及 applicability/requirement/reason，替代此前仅五字段的限制。正式示例会去掉尾随逗号，使用合法 JSON。
- FAILED 返回身份标识、status、reason；任务未创建返回 {"reply":"任务未创建"}。
- 从材料文档提取展示字段；查不到时来源系统填“上银办”、发布日期填“2026年”、发布部门填“上海银行”。其余展示字段沿用缺失置空约定，发布日期不再强制完整日期格式。
- 已知有押品而类型空时，按有押品、类型未知理解，可能适用材料保留；若第二轮 R17 末尾的问号表示该处理尚未决定，可直接更正此项。
- 第二轮 R18 对担保人给出例外：即使批复明确无担保，JSON 有担保人时仍使用 JSON 展开其材料。此例外扩展到哪些关联字段，见 T07。
- 模型节点允许分批及有限重试；API 地址、模型名、密钥部署时配置。部署、权限及脱敏细节本轮不再重复询问。
