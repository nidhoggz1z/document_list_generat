## 人工期望格式

以下仅为格式示意，不是真实业务预期或模型输出：

```json
{
  "products": ["流动资金贷款"],
  "items": [
    {"productName": "流动资金贷款", "sourceRuleId": "1", "materialName": "[流动资金贷款]担保人A身份证明", "requirement": "人工填写"},
    {"productName": "流动资金贷款", "sourceRuleId": "1", "materialName": "[流动资金贷款]担保人B身份证明", "requirement": "人工填写"}
  ]
}
```

products 是无重复名称数组；items 每个期望对象实例占一条，productName/sourceRuleId 必填，materialName/requirement 可选且只供人工核对。已确定排除或核查项不进入 expected.items。匹配以产品集合及 (productName, sourceRuleId) 的重复次数比较，输出 missingProducts/extraProducts、missingItems/extraItems 及逐规则 coverage（expectedCount/actualCount）。总数也记录。相同原编号的不同规则、对象 A/B 的互换以及相同数量下的语义错误无法用此比较区分，必须对照报告完整 actual 及服务内部代次产物人工核对。程序不依据模型自述判定 OCR 正确。

退出码 0、status=COUNTS_MATCH 只表示数量一致；COUNTS_DIFFER 表示数量差异；ERROR 表示输入、网络、任务或响应异常。所有报告 manualConclusion 初始均为待人工核对，reviewer/reviewDate 为空。缺项提示可能误排，额外项提示可能漏排，具体结论由业务人员结合原文及内部决定核实。
