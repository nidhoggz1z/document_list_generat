# 个性化放款材料清单接口

版本：2.3。更新日期：2026-10-29。状态：输入改为原业务 JSON，服务端下载批复 PDF；内网实链及真实模型业务准确性待部署后联调。

完整业务规则见 [spec.md](./tasks/spec.md)，机器契约见 [OpenAPI](./personalized-checklist.openapi.json)。创建入口使用原 JSON 中的 replyImageUrl 下载文件；现有 `/retrieve` 不变。

2026-10-30 产品匹配更新：个性化任务允许同一产品的名称变体，例如“法人房产按揭贷款”匹配“法人按揭贷款材料清单.docx”。先选同名清单，其余由生成模型从现有候选目录中判断唯一对应项；无法确定或有歧义时 FAILED。批复事实及原产品名保留，结果中 `checklistFileName` 表示实际选用文件；同名匹配不增加模型调用。请求、响应字段与后续材料适用性校验不变。

## 1. 创建任务

`POST /api/v1/tasks`，Content-Type：`application/json`。请求体直接是原业务 JSON，不增加 businessData 包装层，不再上传 file。

| 请求字段 | 类型 | 必填 | 内容 |
| --- | --- | --- | --- |
| bsnEvtId | string | 是 | 业务标识 |
| userNo | string | 是 | 用户标识 |
| taskId | string | 是 | 任务标识 |
| replyImageUrl | string | 是 | 可直接 GET 下载单个批复 PDF 的 HTTP(S) URL；文本/扫描均支持，非空且最大 10 MiB |

业务 JSON 的原字段、层级及含义保持不变。上述四字段必填非空字符串；其他字段及嵌套字段可省略、为空或 null，null 忽略；contractNum/subcontractNum 非必填。字段说明及类型见 OpenAPI。

支持内网域名、内网 IP 及 HTTP/HTTPS，由服务部署所在机器访问链接，不要求调用方或开发机能够访问。链接无需鉴权；不从业务字段读取下载 Token、Cookie 或模型 Key。URL 不允许内嵌用户名/密码、片段或非 HTTP(S) 协议。跟随最多 5 次重定向；单次网络操作超时 30 秒，整个下载最长 60 秒，不自动重试。上游 HTTP 节点的超时建议至少 75 秒。

先完整下载并按实际内容校验，再保存原件、创建任务和入队。下载、PDF 校验或持久化失败直接返回错误，**不创建任务、不终止同业务旧任务、不覆盖历史结果**。PDF 基础校验及 10 MiB 上限沿用现有规则；下载成功后的全文可读性、提取及生成错误仍按原流程通过查询返回 FAILED。

`grtstlRcmbNm` 同时用于当前阶段/担保方式的一级目录过滤，例如 `"放贷"`、`"签约"`、`"抵押、保证"`。放贷与放款同义，多个词任一匹配；一级目录明确属于其他阶段/类型时整目录排除，无阶段词的一级目录保留参与筛选。只匹配一级目录标题，不用子目录或材料名绕过限制。材料适用性不确定时统一排除；话术补充的产品归属或子材料适用性不确定时也不加入。历史结果不重算。详见 [严格审核实施说明](./严格排除与一级目录过滤实施说明.md)。

标识去除首尾空白；约定之外的业务 JSON 字段原样保留，不作为服务配置。旧 multipart 请求返回 400，原请求中的 file 不再使用。

**[generate.request.json](./examples/generate.request.json) 现在就是完整请求体。** 先将其中的 replyImageUrl 替换成部署服务可以访问的真实 PDF 链接。PowerShell 调用示例：

```powershell
curl.exe --max-time 75 -X POST "http://服务器地址:8000/api/v1/tasks" -H "Content-Type: application/json" --data-binary "@docs/sdd/examples/generate.request.json"
```

成功保存并入队后立即返回 HTTP 200，不等待生成：

```json
{"bsnEvtId":"B001","userNo":"U001","taskId":"T001","autoReply":"task created"}
```

同业务新任务终止该业务未完成旧任务，自身新排队尾；不打断其他业务。同业务同任务编号覆盖重跑，不同任务编号历史保留。

## 2. 查询任务

`POST /api/v1/tasks/query`，`application/json`：

```json
{"bsnEvtId":"B001","userNo":"U001","taskId":"T001"}
```

三字段必填。按 bsnEvtId+taskId 查询，userNo 不参与唯一键；已有记录回传该次创建保存的 userNo。查询不重新生成。

| status | 含义 | 响应 |
| --- | --- | --- |
| PENDING | 排队 | bsnEvtId、userNo、taskId、status |
| PROCESSING | 解析、提取、生成或校验中 | 同上 |
| TERMINATED | 被同业务新任务替换 | 同上 |
| FAILED | 已接收任务处理失败 | 上述四字段＋reason |
| DONE | 结果完整且已保存 | 上述四字段＋message、data |

以上状态查询均 HTTP 200。PENDING 示例：

```json
{"bsnEvtId":"B001","userNo":"U001","taskId":"T001","status":"PENDING"}
```

失败示例：

```json
{"bsnEvtId":"B001","userNo":"U001","taskId":"T001","status":"FAILED","reason":"未识别到可售产品"}
```

未创建任务，HTTP 200：

```json
{"reply":"任务未创建"}
```

## 3. 完成响应

完整多产品结构见 [generate.response.json](./examples/generate.response.json)，五条材料目录树示例见 [generate.tree.response.json](./examples/generate.tree.response.json)。样例为契约示例，不代表模型实跑。2026-10-27 起，`items` 替换为目录树，上游需更新解析；不再同时返回平铺材料数组。

根节点：status=DONE、bsnEvtId、userNo、taskId、message=生成完成、data。

| data 字段 | 类型 | 含义 |
| --- | --- | --- |
| generatedAt | string | RFC 3339 时间，含时区 |
| total | integer | 全部目录内 materials 的材料叶子总数，大于零，不计算目录或产品数量 |
| products | array | 每产品 extractedProductName、productName、checklistFileName，单产品也用数组 |
| items | array | 按 products 相同顺序排列的产品目录树，每项 productName、categories；不合并跨产品/主体同名材料 |

2026-10-28：新生成结果不再返回 `data.sourceDocumentHash`，TXT 不再输出 PDF SHA-256；内部仍保存文件的哈希并校验原件。历史 JSON 若含该字段则原样保留，响应模型兼容 `HistoricalTaskResult`。2026-10-29 起输入改为原业务 JSON，通过 `replyImageUrl` 下载批复；`grtstlRcmbNm` 继续用于一级目录过滤，状态处理保持原规则。

`categories` 中的目录递归包含以下字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| categoryId | string | Word 原目录编号，在所属产品/父目录下解释 |
| categoryName | string | Word 原目录名称，不统一不同文档名称 |
| children | array | 子目录，同样结构，无子目录为 [] |
| materials | array | 当前目录直接包含的材料；无直接材料为 [] |

空目录剪除；没有材料的已识别产品保留 `categories=[]`。展示与编号顺序为产品顺序、Word目录顺序，目录内先子目录再直接材料，同一目录Word材料先于Excel独有材料。itemId按此顺序全局连续编号。不同主体不再增加目录层级。

与Word合并的材料沿用Word目录；Excel独有材料由模型从该产品原目录中明确选择，无法确认时按严格口径排除，不再默认放入最后一个一级目录。目录标题作为目录返回，不作为材料计数。

历史DONE查询也返回树：使用原代次的规则/合并产物或Word快照恢复，不读取当前list、不调用模型、不改写数据库；旧Excel独有材料无法恢复目录时归原Word最后一级目录，其他确实无法恢复的放“未分类材料”。材料文字、来源、PDF哈希和生成时间保持，itemId按树展示顺序重排。

新生成结果的每条 `materials` 材料对象固定包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| itemId | string | 本次结果唯一编号 R0001 起 |
| itemType | string | 固定 MATERIAL |
| productName | string | 完整产品名，属于 data.products |
| materialName | string | `[产品名]材料名称（主体名称）（具体要求）`，无主体或要求时省略对应括号，无法提取时为空字符串 |
| sourceSystem | string | 文档有则取原内容，无则“上银办” |
| policyBasis | string | 已知制度及条款，无则空字符串；独立标注的“发布依据”不输出 |
| publishDate | string | 文档日期表达，无则“2026年”；允许仅年份 |
| publishDepartment | string | 文档有则取原内容，无则“上海银行” |
| applicability | string | 固定 APPLICABLE，仅返回已明确适用的材料，内部待确认项排除 |
| requirement | string | 个性化要求，无信息为 `""` |

2026-10-28 格式更新：新材料不再返回 `sourceRuleId`、`reason`，内部审核记录仍保留。历史 JSON 保留旧字段和原内容，响应模型兼容 `HistoricalMaterialItem`；已有存档不改写。元数据支持同一行或分行的中文/英文冒号标签，Word 标注优先，缺失信息沿用原默认值。TXT 只按“具体要求、来源系统、制度依据、发布日期、发布部门”的顺序展示非空值，不输出“发布依据”。

材料叶子不返回纯核查动作、不适用项或排除原因；话术库明确要求的查询件仍按材料输出。旧 SUCCESS/NEEDS_REVIEW、data.status、evidence、warnings、适用性计数、checklistVersion 不对外返回。

## 4. 接收及查询错误

| HTTP | 情况 |
| --- | --- |
| 400 | 请求 Content-Type 不是 application/json，或 JSON 语法无效 |
| 422 | 缺必填、null/空白标识、URL 无效、类型错误或空文件 |
| 413 | PDF 超过 10 MiB |
| 415 | 实际内容非 PDF |
| 502 | 下载链接返回非 200、连接失败、传输中断或重定向失败 |
| 504 | PDF 下载超时 |
| 503 | 无法保存文件/任务或服务不可用 |
| 500 | 未预期内部错误 |

统一 `{"reply":"具体错误说明"}`。拒绝接收不建任务、不改变旧任务。接收后的全文解析、模型、规则错误通过查询返回 FAILED＋reason；不得返回部分 DONE。未知任务的查询是 HTTP 200，不是 404。

## 5. 模型与运行约束

两个节点分别配置完整 URL、API Key、模型名，见 [配置模板](./model-api.env.example)，采用 Chat Completions 兼容协议和 Bearer 鉴权。密钥不由下游业务请求传入。

允许内部拆批和有限重试；全局仅一个有效本地任务，取消本地请求不保证供应商推理已经停止。重启后未完成任务 FAILED，不自动重跑。历史本地保存，规则更新不重新生成历史结果。没有确认的 180 秒总业务超时。

本地服务已具备上述新路径；查询错误的运行 OpenAPI 已统一声明为 ReplyResponse。机器契约保留 OpenAPI 3.0 的 nullable/enum 表达，运行模型可能使用 anyOf/null 或 const 表达；按字段、必填项、类型、枚举和实际响应核对语义，不比较说明文字及自动标题。完成响应及机器契约已改为递归目录树，创建和查询请求示例保持原样。openapi-hiagent.json 保留旧检索契约。
