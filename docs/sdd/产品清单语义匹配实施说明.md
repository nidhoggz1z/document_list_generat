# 产品清单名称变体匹配

2026-10-30 用户授权放宽个性化任务的产品选清单逻辑，明确允许“法人房产按揭贷款”对应“法人按揭贷款材料清单.docx”，修改后用原 JSON 重新真实测试。

实现与验证顺序：

1. 为同名直取、模型选取、非法/缺失/歧义选择、纠错及取消补充回归测试；加入完整管道的原名保留与实际 Word 选取测试。
2. 新增 `src/product_matching.py`，在提取与清单快照之间调用。已有同名清单直接采用，其余交给生成阶段模型从完整现有目录中选择。程序严格核对产品覆盖、唯一选择和目录成员关系，纠错次数使用既有 MODEL_MAX_RETRIES。
3. `task_pipeline.py` 保存 `product-matches`，按所选目录读取原始 Word，再以批复原产品名组织规则与目录。保持原件、文件名与哈希，既不重写批复事实也不重命名用户清单。结果保留批复产品名，checklistFileName 指向实际选用 Word。
4. 更新文档、全量回归、重新打包，并通过真实模型/原 JSON/真实 URL 重测，单独保存本轮数据库、接口响应和报告。

模型只负责候选清单的业务对应，不负责放宽批复来源引用、材料适用性或目录过滤。没有唯一对应项时返回阶段失败。原 `/retrieve` 的名称匹配和历史查询规则保持原接口约定。

真实测试第三轮再次在进入匹配前出现提取校验失败，补充可定位的安全校验代码，并让提取节点沿用 MODEL_MAX_RETRIES 有限纠错。原图、完整页面和上下文保留，原严格校验不变；新增一次非法引用后纠正成功及预算耗尽仍拒绝的测试。没有使用历史提取结果绕过正常流程。
