# 个性化放款材料清单任务服务 Spec

版本：2.3。更新日期：2026-10-29（Asia/Shanghai）。创建入口改为原业务 JSON＋URL 下载，后续规则保持不变。

## 1. 目标、依据与范围

接收原业务 JSON，由服务端通过 replyImageUrl 下载批复 PDF，后台串行处理全部可售产品，检索相应规则并生成个性化材料清单，本地保存供上游轮询及历史查询。

依据：[第一轮答复](./需求澄清与假设清单.md)、[第二轮答复](./第二轮需求澄清清单.md)、[最终答复](./最终待确认问题.md) 及 2026-10-29 用户确认。差异以较新答复为准。接口见 [接口文档](../接口文档.md) 和 [OpenAPI](../personalized-checklist.openapi.json)。本规格替代旧同步生成、multipart 上传、NEEDS_REVIEW 及所有未知字段一律留空等过期约定。

本期不增加前端、主动推送、人工终止、权限系统、代码字典、历史制度库或额外网页检索。业务代码放入 src/，适配 src.tar 打包。2026-10-29 输入调整已获得用户确认并实施，实际内网连通性待部署后验证。

## 2. 流程与输入

### FR-01 创建任务

`POST /api/v1/tasks`，application/json，请求体直接使用原业务 JSON：

- 不增加 businessData 包装层，不再提交 file 文件。
- replyImageUrl：必填非空字符串，HTTP(S) URL，可直接 GET 下载单个批复 PDF，允许内网 IP/域名及最多 5 次重定向。文本 PDF、扫描 PDF 均支持。实际非空且最大 10 MiB（10×1024×1024 字节）。单次网络操作超时 30 秒，整体下载期限 60 秒，不自动重试。
- 必填非空字符串：bsnEvtId、userNo、taskId，去除首尾空白后用于定位与回传。JSON 中必须提供 replyImageUrl，不接受文件上传。
- 其他业务字段可省略、空字符串或 null；null 忽略。contractNum、subcontractNum 非必填。非 null 标量仍用字符串、嵌套使用原数组对象结构；金额为十进制字符串，不采用旧两位小数硬限制。
- 空字段、缺失、空数组通常没有可供补充的事实，不能覆盖批复已明确的信息；有押品但类型未知的例外见 FR-10。
- 不解释没有字典支持的内部码值。保留原字段名及 SubcontractCollateralRels 大小写。
- 约定之外的业务字段可保留为上下文数据，不解释为模型配置、队列控制或文件路径等服务指令。
- 支持用户提供的最多 5 个任务量级；后台处理仍串行。不沿用旧 100 页/100 个从合同/180 秒等未确认限制。

### FR-02 接收校验与错误

必填缺失/null/空白、类型错误、JSON 非法、URL 无效或下载失败、空文件、非 PDF 或超限直接拒绝，不创建 FAILED 任务，不终止旧任务、不覆盖历史。

| HTTP | 情况 |
| --- | --- |
| 400 | Content-Type 不是 application/json，或 JSON 语法错误 |
| 422 | 必填缺失/null/空白、错误字段类型、空文件 |
| 413 | 文件超过 10 MiB |
| 415 | 文件内容不是 PDF |
| 502 | 下载 HTTP/连接/传输/重定向失败 |
| 504 | PDF 下载超时 |
| 503 | 文件/任务不能持久化或服务不可用 |
| 500 | 未预期内部错误 |

统一响应 `{"reply":"具体错误说明"}`。基础类型检查不代替全文可读性检查；已接收 PDF 的损坏、加密、部分不可读在执行阶段 FAILED。

### FR-03 创建成功

先下载并校验 PDF，再保存原件、持久化任务及队列变更，以 HTTP 200 返回：

```json
{"bsnEvtId":"B001","userNo":"U001","taskId":"T001","autoReply":"task created"}
```

不等待提取或生成，不保证后续一定成功。保存失败不返回 task created。文件路径由服务生成，不直接采用 URL、远端文件名或业务编号构造任意路径。

## 3. 任务身份与调度

### FR-04 唯一键及覆盖重跑

- 对外唯一键 `(bsnEvtId, taskId)`；userNo 为必需上下文，不参与唯一键或鉴权。已有记录回传本次创建保存的 userNo。
- 同键相同或不同内容再次创建均覆盖重跑；该键只能查询最新一次，不能查被覆盖旧结果。不同 taskId 历史保留。
- 每次接收内部生成唯一 generationId，文件、队列项、状态、模型返回及结果均关联该代次；代次不对外输出。
- 新请求只有通过接收校验并持久提交才改变旧记录；写入失败不得使旧结果丢失或旧任务被终止。

### FR-05 FIFO 与同业务替换

- 一个有效本地任务工作单元，全局按成功接收顺序 FIFO，不同业务不抢占。
- 新任务成功接收时，终止同 bsnEvtId 的全部 PENDING/PROCESSING 旧任务，旧状态变 TERMINATED，移出队列并取消本地执行；新任务用新序号排队尾。
- 其他 taskId 的 DONE/FAILED/TERMINATED 历史不变。同键覆盖按 FR-04 处理。
- 队列、状态、代次变更需原子提交；并发接收以提交先后形成确定顺序。某业务最后成功接收的任务取代其先前全部未完成任务。
- 旧完成与新替换竞争时，以先提交者为准：旧先提交 DONE 则保留；替换先提交则旧输出不可再发布。

| 初始情况 | 新任务 | 必需结果 |
| --- | --- | --- |
| A1 执行，B1/C1 排队 | A2 | A1 终止，依次 B1→C1→A2 |
| A1 执行，B1/C1 排队 | B2 | B1 终止，A1 继续，随后 C1→B2 |
| A1 执行，A2 等待 | A3 | A1/A2 终止，A3 新排队尾 |
| A1 已完成 | A2 | A1 结果保留，A2 新排队 |

### FR-06 取消及迟到输出

- 在解析、提取、检索、生成、拆批和重试各阶段响应取消；停止旧任务本地模型请求及后续步骤，不等待供应商推理真正结束。
- 用户已接受供应商旧推理可能继续；串行约束针对本服务有效任务，不保证供应商取消后推理不重叠。
- 中断后取全局队头，不让新任务插队；无人工终止接口，新任务失败也不复活旧任务。
- 所有写回同时校验 generationId 是当前代次、状态仍为 PROCESSING。迟到成功/失败不能改变终止或重启失败状态，不能覆盖新代次文件和结果。

## 4. 状态与持久化

### FR-07 状态机

| 状态 | 含义 | 允许后续状态 |
| --- | --- | --- |
| PENDING | 保存成功，排队 | PROCESSING、TERMINATED；重启时 FAILED |
| PROCESSING | 解析、提取、检索、生成、校验中 | DONE、FAILED、TERMINATED |
| DONE | 全部结果已完成并保存 | 当前代次终态 |
| FAILED | 接收后的处理失败 | 当前代次终态 |
| TERMINATED | 被同业务新任务替换 | 当前代次终态 |

同键重建产生新代次，不是终态回退。DONE 与完整结果必须原子发布，不能先改状态后补结果。

### FR-08 本地保存与重启

- 保存任务标识、JSON、PDF、代次、顺序号、状态、原因、时间、提取内容、所用清单快照及内容哈希、最终结果。
- 最小实现采用本地持久化；建议标准库 SQLite 保存任务状态和索引，文件放可配置存储目录。队列顺序持久保存。
- 启动时原 PENDING/PROCESSING 全部置 FAILED，reason 说明服务中断；不自动恢复执行。原终态和结果保留。
- 本期同一存储只有一个服务进程及一个工作单元，禁止多 worker 各自消费或互相恢复对方记录。
- 不设置自动清理期限。规则更新不改写历史 DONE，查询不重新生成。允许保留原文及模型请求内容，但 API Key 不入业务数据、提示词、响应或归档。

## 5. 提取、规则及个性化

### FR-09 全文与产品

- PDF 全文、表格及业务事实必须实际读取；扫描页经视觉能力处理，混合 PDF 不得因已有文本而跳过扫描页。页序和来源信息保留。
- 产品按批复“可售产品”识别，不用授信品种或 JSON 产品代替。相同产品多行只查询一次，汇总各行条件且保留差异，不随意合计金额或覆盖限制。
- 产品按首次出现顺序去重。2026-10-30 起，个性化任务先选择同名清单；非同名产品由生成模型从完整现有目录中判断唯一语义对应项，支持同一业务的名称变体。未知、歧义或选择目录之外的清单均失败。批复产品名、事实与引用保持原样，实际采用的 Word 文件名在结果返回，并固定保存匹配关系及原件快照。
- 无产品、任一清单不存在/损坏/重复、任一产品生成不完整均整次 FAILED，不能部分 DONE。
- 复用 DocumentStore 和 docx_reader，不追加旧 src/data。获取本次所需全部产品的一致规则快照，后续更新不混入本次处理。

### FR-10 事实优先级

- 全部明确事实以批复为准，包括明确“无担保”；JSON 不反向覆盖。最终 T07 取消第二轮 R18 的担保例外。
- 批复未提供的信息由 JSON 补充，例如未列姓名则使用 JSON 的担保人 A/B；未提及不等于明确否定。
- 产品仍必须从批复识别，不能以补充原则回退 JSON 产品。
- 明确有押品而 cltlTp 空时是类型未知，不能判为无押品；批复和 JSON 均无法确定类型时，可能适用材料保留。
- 各事实内部保留来源、产品与主体关联，不能跨人、跨产品套用条件。
- 2026-10-23 开发澄清：无产品关联的 JSON 对象，单产品关联该产品，多产品自动套用全部批复产品；批复限定产品的事实仍只作用于对应产品，批复明确否定优先。
- 全空的押品编号、名称、类型占位对象不表示明确有押品；有编号、名称、类型或批复明确存在证据时才建立押品对象，类型缺失保持未知。
- 同一范围的批复事实冲突时采用原文后出现的明确事实；未提及不覆盖已有明确事实。关键事实名称由提取提示统一，其他事实原样保留。

### FR-11 筛选和展开

- 仅输出需要提交的材料叶子，目录标题作为目录返回，不作为材料计数；纯核查动作通常不输出，2026-10-26 新增话术库明确要求的查询件等按材料输出。
- 每条原明细内部有处理决定：核查项、确定不适用排除、保留并按对象展开。排除项/原因不对外输出，但不能将模型遗漏冒充排除。
- 无法确认不适用的材料保留，内部待确认也输出 applicability=APPLICABLE。所有输出 itemType=MATERIAL，不返回旧人工确认状态。
- 材料来源为 Word 清单及 `list/话术库对应材料.xlsx`，不靠模型常识新增来源外材料。话术库允许补入 Word 未列材料，且优先于 Word 的适用条件；细则见 [话术库实施说明](../话术库补充材料实施说明.md)。
- 话术按完整批复及表格进行语义匹配，必须实际出现并引用页号及连续原文，未命中/不能确定命中不补。命中材料整包加入，不按如需、上市、配偶等条件再次过滤。分组标题不输出，子材料分别输出，“/”表示或。
- 明确关联产品只补该产品，共性条件补覆盖产品，归属不明补全部已识别产品。合同名称按实际产品调整。同产品同主体等效材料合并并沿用 Word 名称、编号及展示信息；笼统落实佐证不代替具体子材料。
- 同一材料涉及 A/B 等不同主体、从合同或押品时分别展开；跨产品同名共性材料也分别保留，不合并。
- materialName 使用“[产品名]主体/对象材料名称（具体要求）”。无主体/额外要求时省略对应部分，不编造姓名；例如“[流动资金贷款]担保人A身份证明”。
- 2026-10-27 确认输出目录树：产品首次出现→Word目录顺序→材料及对象顺序。目录内先子目录再直接材料；同目录 Word 材料先于 Excel 独有材料。itemId 按树展示顺序全局从 R0001 连续编号；sourceRuleId 保留 Word 原编号，Excel 独有材料用 `话术库:行15:材料2` 等定位编号，可跨产品和主体重复。
- 目录使用原编号/名称，支持多层，不强行统一各产品名称。不增加主体目录，空目录剪除；已识别但没有材料的产品保留空categories。Excel合并材料沿用Word目录，独有材料允许模型选择本产品Word已有目录，无法确认时放该Word最后一个一级目录。
- requirement 放具体要求，reason 放事实和规则支持的保留理由；材料名称同时按用户要求体现必要个性化描述。

### FR-12 五个展示字段

| 字段 | 有内容时 | 缺失值 |
| --- | --- | --- |
| materialName | 原材料名＋产品前缀＋主体及具体要求 | 空字符串，不编造 |
| sourceSystem | 对应材料文档明确内容 | 上银办 |
| policyBasis | 已知制度名称、文号、对应条款，可只填已知部分 | 空字符串 |
| publishDate | 材料文档中明确的日期表达 | 2026年 |
| publishDepartment | 材料文档中明确部门 | 上海银行 |

缺省值由程序统一补齐。日期是字符串，可仅年份，不强制完整年月日；不把批复起始日、文件修改时间或“2026年版”推导成发布日期；不联网补查。展示字段不输出 null。

### FR-13 模型与完整性

- 两个阶段用 Chat Completions 兼容 HTTP JSON API，Bearer API Key；分别配置完整 URL、Key、模型名，实际值部署时换。
- 文本 PDF 可本地抽取后给提取模型；扫描页渲染图像给具备视觉能力的提取模型。不能只传文件名便假设读取完成。
- 生成上下文包含业务 JSON、完整批复提取内容、全部匹配产品规则全文；拆批也要覆盖上述上下文，不静默截断。容量不够且无法完整组织时 FAILED。
- 2026-10-23 T17 开发澄清：不设置上下文或输出容量上限，不做调用前容量检查；供应商容量错误或输出截断仍 FAILED，不返回部分结果。结构修复额外次数复用 MODEL_MAX_RETRIES；对象范围的业务准确性留给 T28 验收。
- 允许按页/材料拆批、有限重试及结构修复；重试预算可配置，不能无限循环，重试及批次间检查取消。
- 文档文字作为业务数据，不作为系统指令；产品、规则、主体及输出内容须有来源依据。
- 校验结构、产品集合、原规则处理覆盖、主体展开、编号唯一、总数及截断。内部保留原规则处理记录用于核对，不额外对下游返回 evidence。
- 话术库使用每次处理读取的完整原件快照，保存哈希、行索引及匹配记录，更新不改变本次及历史。文件缺失、损坏、不完整或命中材料整包校验失败均 FAILED；不影响 Word 全文检索。
- 任一批次失败、缺页、漏处理规则、结构修复失败、服务不可用或输出容量不足均 FAILED；最终 items 为空也 FAILED。
- 无已确认的 180 秒总任务期限；实际调用仍需可配置网络超时和有限重试，避免无响应永久占队列。这些配置不是业务 SLA。

## 6. 查询与完成结构

### FR-14 查询状态

`POST /api/v1/tasks/query`，application/json，必填非空 bsnEvtId、userNo、taskId。仅按业务编号和任务编号查持久记录，不重新生成。

| 场景 | HTTP | JSON |
| --- | --- | --- |
| 不存在 | 200 | 只有 reply=任务未创建 |
| PENDING/PROCESSING/TERMINATED | 200 | bsnEvtId、userNo、taskId、status |
| FAILED | 200 | 上述四字段＋非空 reason，无 data |
| DONE | 200 | status、bsnEvtId、userNo、taskId、message、data |
| 参数错误 | 400/422 | reply=具体错误说明 |

读取同一已提交快照，不能混用新代次状态和旧代次结果。DONE 的 message 固定为“生成完成”。

### FR-15 DONE 数据

- data.sourceDocumentHash：原始 PDF 字节 SHA-256，64 位小写十六进制。
- data.generatedAt：完成时间，RFC 3339 含时区。
- data.total：目录树中所有材料叶子数量，大于零，不统计目录/产品数量。
- data.products：每项 extractedProductName、productName、checklistFileName；单产品也用数组。
- data.items：产品数组，每项productName、categories。目录递归包含categoryId、categoryName、children、materials；编号、名称和顺序来自该产品Word。materials叶子保留itemId、sourceRuleId、itemType、productName、materialName、sourceSystem、policyBasis、publishDate、publishDepartment、applicability、requirement、reason。
- 历史DONE也只读转换为树，优先使用原代次规则/合并产物及Word快照恢复，不读当前规则、不调用模型、不覆盖历史。旧Excel材料无目录时放原Word最后一级目录，其他无法恢复归入未分类材料；原材料、哈希及生成时间不变，ID按展示顺序重排。
- item.productName 必须属于 products；所有匹配产品必须处理完。某产品可无保留项，但整次无材料则 FAILED。
- 不再返回旧 code/requestId 包装、data 内 status、evidence、warnings、适用性计数、checklistVersion；清单版本和诊断信息内部保存。
- 样例是手写契约数据，不代表真实模型输出。实际结果必须完整，无省略号或默认截断。

## 7. 验收条件

| 编号 | 场景及期望 |
| --- | --- |
| AC-01 | 直接接收原业务 JSON，通过 replyImageUrl 下载并校验单个 PDF，持久化后创建成功，无需等模型；此时任务已可查询。下载失败不影响旧任务。 |
| AC-02 | 缺/null/空白标识、无效 JSON、空/非 PDF、超限拒绝，旧任务及结果不受影响。 |
| AC-03 | 模拟文件或状态保存失败，不返回成功，不出现部分替换。 |
| AC-04 | PENDING→PROCESSING→DONE，查询不调用模型，结果保存后可复查。 |
